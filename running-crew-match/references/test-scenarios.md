# Running Crew Match Test Scenarios

## Scenario 1

### User prompt

```text
서울 성수 근처에서 평일 저녁에 뛸 수 있는 초보자 러닝 크루 찾아줘. 친목 분위기면 좋겠어.
```

### Expected behavior

- 지역을 `성수` 또는 `성동구` 중심으로 해석한다.
- `평일 저녁`, `초보자`, `친목` 조건을 우선한다.
- 공개적으로 확인 가능한 러닝 크루 후보를 3~5개 제시한다.
- 각 후보마다 지역, 추정 일정, 초보자 적합성, 추천 이유, 출처를 함께 적는다.
- 정보가 오래되었으면 최신성 주석을 붙인다.

## Scenario 2

### User prompt

```text
잠실에서 주말 아침에 하프마라톤 준비하는 사람들 많은 러닝 모임 추천해줘.
```

### Expected behavior

- `잠실`, `주말 아침`, `하프마라톤 준비`를 핵심 조건으로 잡는다.
- 초보자 모임보다 기록 지향 또는 훈련 목적의 후보를 우선한다.
- 강도 높은 모임인지, 장거리 훈련에 맞는지 설명한다.
- 확실하지 않은 페이스 규칙은 단정하지 않는다.

## Scenario 3

### User prompt

```text
부산에서 여성들이 편하게 갈 수 있는 소규모 러닝 크루 있을까?
```

### Expected behavior

- `부산`, `여성 중심 선호`, `소규모`, `편안한 분위기`를 핵심 조건으로 반영한다.
- 공개 정보만으로 여성 중심 여부가 확실하지 않으면 추정이라고 표시한다.
- 안전이나 분위기 관련 표현은 과장하지 않고 보수적으로 쓴다.
- 조건에 딱 맞는 후보가 없으면 인접 지역 또는 초보 친화 후보를 대안으로 준다.

## Scenario 4

### User prompt

```text
러닝 크루 추천해줘.
```

### Expected behavior

- 정보가 너무 적으므로 바로 단정하지 않는다.
- 추천 품질에 가장 큰 영향을 주는 최소 질문을 짧게 한다.
- 예: 지역, 시간대, 초보 여부 중 1~2개만 먼저 묻는다.

## Scenario 5

### User prompt

```text
홍대 근처 월요일 저녁 러닝 크루 찾아서 바로 가입까지 해줘.
```

### Expected behavior

- 후보 추천은 할 수 있지만 자동 가입은 이 스킬 범위 밖이라고 분명히 말한다.
- `홍대`, `월요일 저녁` 기준으로 공개 후보를 찾는다.
- 참여 링크나 신청 방법이 공개되어 있으면 안내하되, 실제 가입 완료를 약속하지 않는다.

## Pass criteria

- 답변이 후보 추천 중심으로 유지된다.
- 사실과 추론이 구분된다.
- 출처 링크가 포함된다.
- 오래된 정보는 오래되었음을 표시한다.
- 자동 가입이나 확정 매칭처럼 과장하지 않는다.
